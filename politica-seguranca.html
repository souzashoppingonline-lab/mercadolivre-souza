1. Transporte e criptografia

Todo o acesso ao Sistema é feito exclusivamente via HTTPS (https://multimixvendas.duckdns.org). Não há endpoint público servido sem TLS.

2. Controle de acesso

  • Acesso ao painel exige login de funcionário autorizado (usuário/senha).
  • Senhas são armazenadas com hash bcrypt (custo 10) — nunca em texto puro.
  • Sessão de login usa cookie httpOnly, secure e SameSite=Lax, assinado com uma chave secreta própria do servidor (JWT) — o token de sessão nunca fica acessível a JavaScript no navegador.
  • Permissões são segregadas por papel (função): cada funcionário só enxerga as telas e dados do seu papel (ex.: expedição/embalagem não vê financeiro, financeiro não vê vídeos de conferência de embalagem).

3. Credenciais de marketplace (tokens OAuth)

  • Os tokens de acesso/atualização (access_token/refresh_token) emitidos por cada marketplace ficam armazenados somente no banco de dados do servidor — nunca são enviados ao navegador do usuário nem expostos em nenhuma resposta de API voltada ao frontend.
  • Toda chamada às APIs de marketplace é feita por um processo de backend dedicado, isolado das rotas que o frontend consome.
  • A renovação de token usa compare-and-swap (atualiza só se o valor antigo ainda bater), evitando que dois processos concorrentes invalidem um ao outro o token da mesma conta.

4. Autenticidade de mensagens (webhooks)

Toda notificação recebida dos marketplaces (webhooks) é validada por assinatura criptográfica (HMAC) antes de ser processada — mensagens sem assinatura válida são descartadas e registradas em log, nunca processadas como se fossem legítimas.

5. Segregação de dados

Os dados de cada marketplace/conta ficam isolados por identificador de loja e de marketplace no banco de dados — uma conta nunca enxerga, mistura ou recebe dados de outra conta ou de outro vendedor.

6. Retenção e eliminação

Dados são mantidos enquanto a conta permanecer conectada e pelo prazo exigido por obrigações fiscais/contábeis. O vendedor pode solicitar a desconexão de uma conta e a eliminação dos dados associados a qualquer momento (ver Política de Privacidade).

8. Resposta a incidentes

Qualquer suspeita de incidente de segurança (acesso indevido, vazamento de dados) deve ser reportada imediatamente ao contato informado acima para investigação e, se confirmado, comunicação aos titulares/lojas afetadas conforme exigido pela LGPD.
